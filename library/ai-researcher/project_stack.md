# Project Stack & Specifications

## Purpose
A devcontainer that runs `llama-server` (from llama.cpp) on an NVIDIA GPU and exposes it to `opencode` as local LLM providers through a Bifrost gateway. Used for AI-assisted coding entirely offline / locally (the hosted `opencode` Console is the only cloud path, and only for the primary agent fallback).

## Software Stack
- **Loader:** llama.cpp `llama-server`, installed by the `llama-server` feature from the official GGML ubuntu-bin asset (b10360 era) and symlinked to `/usr/local/bin/llama-server`. Started by `scripts/auto-startup.sh` — one server per model declared in `stack.json`. (Historical note: the upstream lab ran a custom Gemma-4 fork launcher at `/opt/llama-server/`; the shipped feature installs the stock GGML binary, so flag-check the binary itself, not a custom launcher.)
- **Gateway:** Bifrost (`@maximhq/bifrost`) on port 8082, launched via `/usr/local/bin/start-bifrost`. Config `config/bifrost.json` is materialized by `write-bifrost-config.sh` from `stack.json` — one provider per llama-server upstream, routed by `keys[].models = ["{name}*"]`.
- **Orchestrator:** opencode serve on `stack.json.opencode_port` (default 4096). `opencode.json` is materialized by `generate-opencode.sh`/`generate-opencode.jq` from `stack.json`.
- **Base image:** `nvidia/cuda:13.3.0-cudnn-runtime-ubuntu24.04`. Python 3.12 provisioned; node/npm/jq provisioned by the features that need them.

## The shared manifest (`stack.json`)
Single source of truth, written by the `models` feature to `/usr/local/share/llm-lab/stack.json`:

```
schema: 1, models_dir, bifrost_port, opencode_port, subagent_depth
cloud, cloud_provider
models[]: { name, provider, hf, quant, port, context, parallel }
roles{}:  { role -> { model, slot } }
```

- `name` = the model id family used everywhere (`provider.models`, `--alias`, bifrost routing prefix). Keep it short and machine-friendly (e.g. `gemma4-26b-a4b`), NOT the HF slug.
- `provider` = the opencode provider id (`local-<name>` by convention).
- `port`/`context`/`parallel` = per-server values (`--port`/`--ctx-size`/`--parallel`).
- `roles` maps each agent role to `{model, slot}`; slots are 0..`parallel-1`.
- **Cloud mode (`cloud: true`):** `models[]` is EMPTY and `roles[].model` is a hosted `opencode` provider model id (default `big-pickle`). Slot is unused (`generate-opencode.jq` emits `opencode/<model>` per role, no local providers/bifrost). Written when `CLOUD_MODE=true` and no explicit `MODELS` are supplied; explicit `MODELS`/`.devcontainer/llm-lab-models.json` ALWAYS win and force `cloud: false`.
- Consumer override precedence: feature option env var > `$PWD/.devcontainer/llm-lab-{models,roles}.json` > built-in defaults.
- Regeneration: edge of the `models` feature; downstream configs (bifrost, opencode) are regenerated by re-running their generators, or by rebuild of the features that read the manifest.

## Model Specifications
- **Production default:** Gemma 4 26B A4B IT (MoE: 25.2B total / 3.8B active, 128 experts + 1 shared, top-8 routing, 30 layers, 256K ctx, built-in thinking mode, native function calling), unsloth UD-GGUF `gemma-4-26B-A4B-it-UD-IQ2_M.gguf` (9.33 GiB — fits ENTIRELY in 12 GB VRAM). Manifest `name`/alias: `gemma4-26b-a4b` on port 8089, context 65536, parallel 5. See `library/ai-researcher/gemma-4-26b-a4b.mini.md` for the model reference.
- **Slot ids** (`gemma4-26b-a4b-s0..s4` in `opencode.json` provider models): client-side labels for the agent→slot pinning in `roles`. In single-model mode llama-server ignores the `model` field and assigns an idle slot (`id_slot` / idle-slot pick); the opencode side selects agents' slots and the bifrost layer routes by the `{name}*` prefix. The slots' shared context pool is `--ctx-size` (uniform `context` per model, unlike the historical per-slot 65536/49152/32768 curation).
- **Additional models:** any extra entries in `stack.json.models[]` each get their own llama-server (own `port`), their own opencode provider, and their own bifrost upstream. Roles pin onto whichever model/slot they reference.
- **Other enabled provider:** `opencode` (hosted Console control path; MUST carry the `setCacheKey=false` options — see Conventions). In cloud mode it is the ONLY provider: every `agent.<role>.model` = `opencode/<cloud model id>` (default `big-pickle`), and `enabled_providers = ["opencode"]`. Legacy one-off providers (`local-gemma4-12b`, `local-gemma4-31b`, `local-nemotron`, `local-qwen3`) are no longer generated.

## Serving contract (auto-startup.sh)
`start_llama_server` launches each model as:

```
llama-server -m <models_dir>/<hf>_<quant>.gguf \
    --host 0.0.0.0 --port <model.port> \
    --ctx-size <model.context> --alias <model.name> --parallel <model.parallel>
```

- **Model ID sync (REQUIRED):** `stack.json.models[].name` == `--alias` passed to llama-server == the `provider.models` id family in the generated `opencode.json` == the bifrost `keys[].models` prefix (`{name}*`). A mismatch 404s completion requests (bifrost can't route to an upstream).
- **Legacy no-manifest fallback:** first `models_dir/*.gguf`, port 8089, ctx 65536, alias `gemma4-26b-a4b`, `SLOTS` (default 5) — matches the shipped `opencode.json.fragment`.
- Header `x-bf-passthrough-extra-params: true` on opencode provider options lets `id_slot` reach llama-server.

## Environment & Hardware
- **GPU:** NVIDIA GPU, **12 GB VRAM** (measured ceiling ≈12.2 GiB for the 26B IQ2_M profile).
- **CUDA Architectures:** 80, 86, 89, 90, 120 (Ampere, Ada, Hopper, Blackwell).
- **Older cards:** add `75` to `CMAKE_CUDA_ARCHITECTURES` in the `llama-server` Dockerfile on Turing if "no kernel image available" errors occur.

## Project Conventions
- **Context limits:** change the `context` field in `stack.json` (or the `MODELS` option in the `models` feature) and regenerate — `auto-startup.sh` passes it as `--ctx-size` and `generate-opencode.jq` emits the same value as `limit.context`. The two MUST match so opencode's context tracker is accurate. (Cloud mode inherits hosted defaults — no `limit` emitted.)
- **Cloud-mode routing (v1.2.0):** `CLOUD_MODE=true` with no explicit `MODELS` writes `stack.json.cloud=true`, empty `models[]`, and hosted-openmodel role ids; `generate-opencode.jq` then pins every agent to `opencode/<role.model>`; `auto-startup.sh` skips llama-server AND bifrost. Explicit `MODELS`/`ROLES` always build the local stack (cloud flag forced false).
- **Hosted provider fix (REQUIRED):** `provider.opencode.options.setCacheKey = false` — opencode injects `prompt_cache_key` into requests to any provider whose `providerID` starts with `"opencode"`; the hosted backend rejects that argument. Without this override every hosted completion fails.
- **Model storage:** keep `models/` gitignored. Never commit `.gguf` files; use `/usr/local/share/llm-lab/models/fetch-models.sh` (iterates `stack.json` models) for reproducibility.
- **gpg:** `commit.gpgsign=true` is set but gpg fails in some environments — commit with `git -c commit.gpgsign=false commit` (unset config if desired).
